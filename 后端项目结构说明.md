# 心理健康AI助手 - 后端项目结构说明

> 项目路径：`e:\简历项目\心理健康助手\后端代码\ai-spingboot`
> 技术栈：Java 17 + Spring Boot 3.5 + Spring AI 1.0 + Spring Security + JWT + MyBatis-Plus + MySQL 8
> 服务端口：`1236`，接口统一前缀 `/api`

## 三、启动类

- `AiSpingbootApplication.java`：`@SpringBootApplication` 启动类，`main` 方法调用 `SpringApplication.run`。默认扫描 `org.example.aispingboot` 下所有组件。

## 四、config —— 配置层（`application.yml` 是 配置文件（数据） ，`config` 包是 Java 配置类（代码） ）

### ChatClientConfig.java

构建 AI 对话所需的两个 Bean：

- `chatMemory()`：`MessageWindowChatMemory`，`maxMessages = 30`，即每个会话最多保留最近 30 条消息作为上下文。
- `openAiChatClient(...)`：基于 `OpenAiChatModel` 构建 `ChatClient`，Bean 名 `open-ai`；默认挂载 `MessageChatMemoryAdvisor`，并设置默认系统提示词。

### JwtConfig.java

`@ConfigurationProperties(prefix = "jwt")`，把 `application.yml` 中的配置绑定为对象：

- `secret`：HMAC256 签名密钥
- `expiration`：访问 token 有效期
- `refreshExpiration`：刷新 token 有效期（当前代码未实际使用）
- `header` / `tokenPrefix`：配置项存在，但当前过滤器实际读取的是请求头 `token`

### SecurityConfig.java

- `@EnableWebSecurity`、`@EnableMethodSecurity`
- 关闭 CSRF（api服务通常不需要）
- 会话策略设为 `STATELESS（无状态）`（适合 JWT）
- 公开路径 `PUBLIC_PATHS（数组）`：`/（根路径）`、`/api/test`、`/api/user/login`、`/api/user/add`
- 其他请求全部要求认证
- 把自定义 `JwtAuthticationFilter` 添加到 `UsernamePasswordAuthenticationFilter` 之前
- `isPublicPATH(uri)` 用 Ant 路径匹配，供过滤器判断是否跳过

## 五、common / exception —— 统一响应与异常

### Result.java

统一响应结构：

```json
{ "code": "200", "msg": "操作成功", "data": ... }
```

提供 `ok()`、`ok(data)`、`error()`、`error(code, msg, data)` 静态方法。

### ResultCode.java

业务码枚举，常用值：

| 枚举                              | code    | 含义                 |
| ------------------------------- | ------- | ------------------ |
| SUCCESS                         | `200`   | 操作成功               |
| ERROR                           | `-1`    | 操作失败（前端拦截器据此清理登录态） |
| UNAUTHORIZED                    | `401`   | 未登录或 token 过期      |
| PARAM\_ERROR                    | `400`   | 参数错误               |
| USER\_NOT\_EXIST                | `6002`  | 用户不存在              |
| TOKEN\_INVALID / TOKEN\_EXPIRED | `A0230` | token 无效 / 过期      |
| ACCESS\_UNAUTHORIZED            | `A0301` | 访问未授权              |

### GlobarExceptionHandler.java

`@RestControllerAdvice` 全局异常处理：

- `MethodArgumentNotValidException`：收集所有字段校验错误，用逗号拼接后返回 `400`
- `BusinessException`：返回异常自带的 `code`、`message`、`data`

### BusinessException.java

业务运行时异常，默认 code 为 `BUSINESS_ERROR`，携带 `message` 和可选 `data`。

| 方法   | 路径                                      | 说明                                      |
| ---- | --------------------------------------- | --------------------------------------- |
| POST | `/api/psychological-chat/session/start` | 创建咨询会话，保存首条用户消息，返回 `session_N` 形式的会话 ID |

- 每段数据之间 `delayElements(50ms)`，保证前端能看到逐字输出效果

## 七、AiService —— AI 对话核心

### PromptManage.java

存放心理疏导系统提示词 `PSYCHOLOGICAL_SUPPORT_SYSTEM_PROMPT`，内容覆盖：

- 角色定位：温暖、有同理心的 AI 心理健康助手，面向大学生
- 对话原则：先共情、再梳理情绪、提供温和建议、必要时鼓励求助
- 特殊处理：检测到自杀倾向时优先表达关心并引导专业帮助；严重问题建议联系学校心理咨询中心
- 回复要求：简体中文、长度适中、贴近大学生场景

### PsychologicalSupportService.java

核心业务：

1. **startSession(userId, DTO)**
   - 校验用户是否存在，创建 `consultation_session` 记录
   - 标题为空时自动生成 `AI助手 - MM-dd HH:mm`
   - 把首条用户消息写入 `consultation_message`
   - 返回 `StructOutPut.StreamChatSession`，会话 ID 形如 `session_17`
2. **streamPsychologicalChat(sessionId, userMessage)**
   - 从 `session_N` 中解析数据库会话 ID
   - 查询当前消息数；如果只有 1 条且内容与本次输入相同，判定为“初始消息”，不再重复入库
   - 否则先保存用户消息
   - 以 `conversation_session_N` 作为 ChatMemory 的会话标识
   - 把用户消息加入 ChatMemory，构建 `SystemMessage + UserMessage` 的 Prompt
   - 调用 `chatClient.prompt(...).stream().content()`，边接收边通过 `Flux` 向前端推送
   - 用 `StringBuilder` 汇总完整回复，流结束后保存 AI 消息（`senderType=2`、`aiModel=openai`）并写回 ChatMemory
3. **extractSessionId(sessionId)**
   - 校验前缀 `session_` 并解析为 `Long`

### StructOutPut.java： AI 对话相关的结构化输出定义

用 Java `record` 定义 `StreamChatSession`，字段：

`sessionId`、`userHash`（实际为 userId）、`initialMessage`、`startTime`、`expiryTime`（24 小时）、`messageCount`、`status`

## 十一、mapper —— 持久层

三个 Mapper 都继承 MyBatis-Plus 的 `BaseMapper<T>`，无需手写 SQL 即可使用：

- `UserMapper`：用户 CRUD
- `ConsultationSessionMapper`：会话 CRUD
- `ConsultationMessageMapper`：消息 CRUD

复杂条件通过 `LambdaQueryWrapper` 在 Service 中拼接，例如登录时 `username = ? OR email = ?`、查询最后一条消息时按 `createdAt` 倒序 `limit 1`。

## 十二、service —— 业务层

### UserService.java

- `login(...)`：按用户名或邮箱查询用户；校验密码（BCrypt）；校验状态；生成 JWT；转换为登录响应
- `register(...)`：校验两次密码一致、用户名唯一、邮箱唯一、用户类型合法；BCrypt 加密后入库
- `getUserById(...)`：查询用户并转 DTO；JWT 过滤器每次请求也会调用它校验用户状态

### ConsultationSessionService.java

- `createSession(userId, DTO)`：校验用户存在；创建会话；标题为空时生成默认标题；插入数据库

### ConsultationMessageService.java

- `saveUserMessage(...)`：保存用户消息，`senderType=1`
- `saveAimessage(...)`：保存 AI 消息，`senderType=2`
- `getMessageCountBySessionId(...)`：统计会话消息数
- `getLastMessageBySessionId(...)`：取最后一条消息并转 DTO，用于判断初始消息是否重复

### convert/UserConvert.java

手工转换工具：

- `entityToDetailResponse(User)`：实体 → 用户详情 DTO，补充性别、类型、状态显示名称
- `entityToLoginResponse(token, userInfo)`：组装登录响应
- `registerCommandToEntity(DTO, encodedPassword)`：注册入参 → 实体，默认状态为正常

## 十三、util —— 安全与响应工具

### JwtTokenUtil.java

- `generateToken(userId, username, roleType)`：HMAC256 签名，写入 `userId`、`username`、`roleType`，设置签发时间、过期时间、issuer
- `extractTokenFromRequest(request)`：从请求头 `token` 读取
- `getCurrentToken()`：优先取过滤器放入的 `jwtToken` 请求属性，否则回退读请求头
- `verifyToken(token)`：校验签名、issuer、过期时间，失败抛 `JWTVerificationException`
- `validateToken(token)`：解析并封装 `TokenVerificationResult(userId, username, roleType, valid)  `

即：verifyToken 负责"这个 token 是不是真的、
&#x20;    \* 有没有过期"，validateToken 负责"从真的 token 里取出用户身份

<br />

"继承 `OncePerRequestFilter`，每个请求执行一次：

1. `shouldNotFilter`：公开路径直接跳过
2. 提取 token；为空则写 401 并结束
3. 校验 token；失败写 `TOKEN_INVALID`
4. 查询用户并校验状态；禁用用户写 `TOKEN_ACCESS_FORBIDDEN`
5. 构造 `UsernamePasswordAuthenticationToken`，权限为 `ROLE_ + roleType`
6. 写入 `SecurityContextHolder` 和请求属性 `jwtToken`
7. 放行到后续过滤器

### ResponseUtil.java

过滤器内无法使用 `@RestControllerAdvice`，因此直接向 `HttpServletResponse` 写 JSON：

- 401：未登录、token 无效/过期/拉黑
- 403：token 被禁止访问
- 400：其他默认情况

## 十七、核心调用链

### 登录

```
POST /api/user/login
  → UserController.login(@Valid UserLoginCommandDTO)
  → UserService.login()
      → UserMapper.selectOne(username 或 email)
      → BCryptPasswordEncoder.matches()
      → UserStatus 校验
      → JwtTokenUtil.generateToken()
      → UserConvert.entityToLoginResponse()
  → Result.ok(token + userInfo)
```

### AI 流式对话

```
POST /api/psychological-chat/session/start
  → 解析 token 中的 userId
  → ConsultationSessionService.createSession()
  → ConsultationMessageService.saveUserMessage()
  → 返回 session_N

POST /api/psychological-chat/stream
  → JwtAuthticationFilter 认证
  → PsychologicalSupportService.streamPsychologicalChat()
      → 解析 session_N
      → 判断/保存用户消息
      → ChatMemory.add(conversation_session_N)
      → ChatClient.stream().content()
      → Flux<String> 增量
  → 包装为 ServerSentEvent("message", Result JSON)
  → concatWith(done) + 50ms 延迟
  → 前端 fetch-event-source 逐段渲染
```

### 普通受保护接口

```
请求
  → JwtAuthticationFilter
      → 公开路径？跳过
      → 读取 header.token
      → 验签 + 查用户 + 校验状态
      → 写入 SecurityContext
  → Controller
  → Service
  → Mapper
  → MySQL
  → Result
```

## 十八、当前实现范围与注意事项

1. **已完整实现**：用户登录/注册/当前用户、JWT 认证、AI 会话创建、SSE 流式对话、会话与消息落库。
2. **未实现**：知识文章管理、情绪日记、收藏、文件上传、后台统计等接口。前端对应页面当前通过代理访问远程完整后端，本地后端只覆盖上述能力。
3. **配置与代码不一致**：`application.yml` 配置了 `jwt.header: Authorization` 和 `token-prefix: Bearer `  ，但 `JwtTokenUtil` 实际读取的是请求头 `token`；前端 `request.js` 也使用 `token` 头，因此能正常联调。
4. **AI 配置安全**：DeepSeek API Key 明文存放，建议改为环境变量；此前使用其他平台 Key 时曾出现 `401 Token is invalid`。
5. **依赖冗余**：`spring-boot-starter-data-jdbc` 当前未直接使用，持久层主要走 MyBatis-Plus。
6. **异常处理范围有限**：`GlobarExceptionHandler` 只处理参数校验和业务异常，未兜底通用 `Exception`。
7. **代码拼写**：包名 `AiService`、类名 `GlobarExceptionHandler`、工程名 `ai-spingboot` 为现有拼写，重命名会影响较大范围，暂保持原样。
